## Перед завантаженням у Console

1. Зібрати AAB (якщо потрібна свіжа збірка):
   ```bat
   gradlew.bat :app:bundleRelease '-PreleaseTag=v1.13.0'
   ```
   Файл: `app\build\outputs\bundle\release\app-release.aab`

2. Переконатися, що **той самий ключ підпису**, що для GitHub Releases — інакше користувачі не оновляться з APK.

3. Прогнати тести:
   ```bat
   gradlew.bat testDebugUnitTest lintDebug
   ```

## Підтвердження розробника Android — до 30 вересня 2026

Сторінка: **Перевірка розробника Android** у боковому меню Console
(`…/android-developer-verification`). Звірено 24 вересня 2026.

**Основний застосунок — усе гаразд.** Пакет `app.bookvoices` має стан
«Зареєстровано» (з 5 вересня), ключів 4, усі «Підтверджено». Серед них — ключ,
яким підписані APK на GitHub Releases (відбиток `34:83:20:68:EA:D9:…`, той самий,
що Play App Signing і що показав крок «Перевірити підпис» у релізі v1.13.0).
Тобто APK з GitHub після 30 вересня не втрачають можливості встановлюватися.

**Хмарний клієнт — не зареєстровано.** `app.bookvoices.cloud` (окремий
приватному релізі GitHub поряд з основним. У публічне дзеркало він не їде. Якщо
цей APK ще стоїть на пристрої й треба, щоб він ставився після 30 вересня на
сертифікованих пристроях у частині країн, — «Зареєструвати назву пакета» на цій
сторінці. Хмарний клієнт заморожено, тож це рішення власника, а не вимога.

продажу** (колонки комісії в «Завантаження звітів → Фінансові» / Earnings) або
підтримка Play.

## Рекомендації Console до випуску 11300 (12 жовтня 2026)

Розділ Console з трьома «рекомендованими діями» до 11300 (1.13.0). Жодна не блокує
публікацію й не вимагає змін у `app/`. Розшифровано за `mapping.txt` R8 з
`app/build/outputs/mapping/release` (файл від 25 вересня; збігається зі збіркою 11300,
якщо її не перезбирали з іншого стану).

| Що каже Play | Що це насправді |
|---|---|
| Безрамковий показ (edge-to-edge) може не працювати для всіх | Стандартний текст для targetSdk 35+. У нас `targetSdk = 36`, `MainActivity` уже викликає `enableEdgeToEdge()`. Лишається один раз глянути на Android 15/16, чи відступи не заходять під системні панелі й виріз |
| Застарілі `setStatusBarColor`, `setNavigationBarColor`, `SHORT_EDGES` у `fz0.b`, `hz0.b`, `y2.l` | Код бібліотек, не наш: `fz0` = `androidx.activity.EdgeToEdge`, `hz0` = `EdgeToEdgeApi28`, `y2` = службовий клас `androidx.core`. У `src/main` цих викликів немає. Зникне з оновленням `activity`/`core` |
| `BitmapFactory` без зменшення в `rs0.Z` | Наші два місця (`Components.kt`, `NowPlayingWidgetProvider.kt`) вже ставлять `inSampleSize`. `rs0` у mapping — `androidx.profileinstaller.DeviceProfileWriter`, що для BitmapFactory дивно, тож рядок однозначно не зіставлено; імовірніше бібліотека (наприклад Coil) |

Імена класів міняються між збірками: перед тим як щось «виправляти» за наступним
таким повідомленням, звіряйте з mapping саме тієї збірки, яку розбирає Console.
