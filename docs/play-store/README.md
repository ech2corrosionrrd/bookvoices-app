## Перед завантаженням у Console

1. Зібрати AAB (якщо потрібна свіжа збірка):
   ```bat
   gradlew.bat :app:bundleRelease '-PreleaseTag=v1.12.0'
   ```
   Файл: `app\build\outputs\bundle\release\app-release.aab`

2. Переконатися, що **той самий ключ підпису**, що для GitHub Releases — інакше користувачі не оновляться з APK.

3. Прогнати тести:
   ```bat
   gradlew.bat testDebugUnitTest lintDebug
   ```

## Платежі й SKU

Стан звірено в Console 12 вересня 2026. Персональних даних і номера платіжного
профілю тут навмисно немає: цей файл їде в публічне дзеркало.

**Платіжний профіль уже створено** — тип «фізична особа», податкова інформація,
назва й адреса заповнені. Довгий час у цьому чеклісті стояло, що SKU блокує
«обліковий запис продавця»; це було неточно й виправлено: найважча частина
(податки й реквізити власника) давно позаду.

Живе воно тут: **Налаштування → Монетизація → Платіжний профіль**
(`…/developers/<id>/paymentssettings`). Прямого шляху `settings/payments-profile`
не існує — він просто кидає на список додатків.

### Що лишилося зробити руками

**1. Публічний профіль продавця.** Форма на тій самій сторінці, чотири поля, три
з них обовʼязкові:

| Поле | Що ставити |
|---|---|
| Назва компанії | `BookVoices` — галочка «використовувати офіційні дані» поля не заповнює |
| Що ви продаєте | випадний список; у нас цифровий контент / застосунки |
| Електронна адреса підтримки | та сама, що в політиці конфіденційності — інакше в користувача буде дві різні адреси підтримки |
| Назва для виписки з кредитної картки | `BOOKVOICES`; незрозумілий рядок у банківській виписці — прямий шлях до повернень коштів |
| Веб-сайт | необовʼязково; підходить публічне дзеркало |

Це та форма, після якої відкривається створення SKU.

**2. Спосіб отримання платежів.** Картка «Як ви отримуєте платежі» порожня.
Це банківські реквізити (для України — IBAN), і Google підтверджує їх пробним
зарахуванням, тож закладайте кілька днів.

**Але продавати це не блокує.** Реквізити потрібні лише щоб забрати зароблене;
SKU і покупки працюють без них.

**3. Знижена комісія 15 %.** Сповіщення від 12 вересня 2026: Console пропонує
зареєструватися на ставку 15 % замість 30 % (для доходу до $1 млн на рік).
Потрібно створити групу облікових записів і прийняти умови. Зробити це варто
**до першого продажу** — заднім числом ставку не перераховують.

### Єдине, що сервіс вимагає від Play Console

> Then select all countries, send the changes for review, and publish.

Чотири кроки, і всі чотири мають бути завершені, інакше застосунок показується
тестувальникам як недоступний. Їхній FAQ називає три типові причини: **незбережена
зміна, ненадіслана перевірка, неопублікований дозвіл** — у нас зараз перша.
Третя не загрожує: керовану публікацію в цьому обліковому записі вимкнено.

**Список розсилки «BookVoices internal» (6 адрес) до сервісу стосунку не має.**
Це власні люди, зокрема власна адреса розробника. У режимі «Google Групи» він
просто не бере участі — **видаляти не треба**, інакше доведеться збирати заново.

### Їхній графік

| День | Що | Чий крок |

Тобто від публікації треку до застосунку в Play — близько трьох тижнів.

### Про що варто пам'ятати

Google очікує, що тестувальники — справжні люди, які застосунком користуються.
Спільноти взаємного тестування самі собою не заборонені, але заявку на production
відхиляють, якщо тестування виглядає як порожні установки без активності. Сервіс
на це відповідає гарантією «Production Access Guarantee» — повернення грошей за
застосунок, якщо дозволу не дали. Гарантія повертає гроші, не час.
